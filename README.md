# NOVA WEAR — интернет-магазин одежды

Готовая кодовая база интернет-магазина на **Next.js 15 + React 19 + TypeScript + Tailwind CSS + PostgreSQL + Prisma 6**. Витрина на русском языке, цены в сомах, доставка по Кыргызстану, оплата при получении.

> **Статус:** проект содержит реальную серверную модель товаров/заказов, но **не является развёрнутым коммерческим сервисом**. Для запуска нужны Node.js, зависимости, PostgreSQL и настройка окружения. Онлайн-оплата и уведомления покупателей не подключены. Фотографии в seed — редакционные изображения для оформления и должны быть заменены фотографиями собственных товаров перед приёмом реальных заказов.

## Возможности

- **Главная:** полноэкранная фотография, категории, редакционные блоки, популярные товары, преимущества, подписка, футер.
- **Каталог:** фильтры по категории, полу коллекции, размеру, цвету, цене и скидке; сортировка по новизне, популярности и цене; поиск с выпадающими подсказками.
- **Товары:** галерея, описание, состав, наличие, выбранные размер/цвет, таблица размеров, похожие товары.
- **Корзина и избранное:** сохраняются в `localStorage`, переживают перезагрузку и закрытие вкладки.
- **Заказ:** клиентская/серверная Zod-валидация, пересчёт актуальных цен на сервере, атомарное списание остатков (Prisma PostgreSQL transaction), случайный номер заказа, сохранение в БД. Оплата **только при получении**.
- **Админка:** `/admin/login` и `/admin`; товары, фото, варианты размеров/цветов/остатков, цены, категории, заказы и статусы. Авторизация и права проверяются **на сервере** в каждом endpoint. Пароль хранится как bcrypt hash, сессия — случайный токен, его SHA-256 хэш хранится в PostgreSQL. Cookie `HttpOnly`, `SameSite=Lax`, `Secure` на HTTPS/production. Проверка `Origin` для изменяющих admin-запросов, 15-минутная блокировка после 5 неудачных попыток входа для существующего email.
- **Адаптивность:** мобильное меню, фильтры, мини-корзина, таблицы и формы; скелетон загрузки; уведомления и пустые состояния.

## Системные требования

- Node.js 20.9+ (рекомендуется Node.js 22 LTS)
- npm 10+
- Docker Desktop с Docker Compose или PostgreSQL 16+

## Локальный запуск (Windows PowerShell)

Распакуйте архив, откройте PowerShell в папке `nova-wear`.

```powershell
Copy-Item .env.example .env
```

Откройте `.env` и **обязательно** задайте сложный уникальный `ADMIN_PASSWORD` длиной 16+ символов. При желании замените `ADMIN_EMAIL`. Строка подключения уже настроена на PostgreSQL из `docker-compose.yml`.

```powershell
# 1. PostgreSQL
 docker compose up -d

# 2. Node.js зависимости
 npm install

# 3. Prisma Client
 npm run db:generate

# 4. Таблицы и индексы в PostgreSQL
 npm run db:deploy

# 5. Категории, 18 товаров, учётная запись администратора
 npm run db:seed

# 6. Сайт
 npm run dev
```

Откройте:

- Магазин: **http://localhost:3000**
- Каталог: **http://localhost:3000/catalog**
- Административный вход: **http://localhost:3000/admin/login**

Для входа используйте `ADMIN_EMAIL` и `ADMIN_PASSWORD` из вашего `.env`.

**Примечание:** `npm run db:seed` безопасен для повторного запуска в части каталога — товары добавляются по `slug` только если их нет. Однако повторный запуск обновляет пароль администратора на текущее значение из `.env`.

### Linux/macOS

```bash
cp .env.example .env
# Настройте ADMIN_PASSWORD в .env

docker compose up -d
npm install

npm run db:deploy
npm run db:seed
```

Если порт 5432 занят, измените опубликованный порт в `docker-compose.yml` и `DATABASE_URL` синхронно. Для собственной PostgreSQL вместо Docker пропишите её URL в `.env`.

## Прочие команды

```bash
npm run typecheck      # TypeScript typecheck (после npm install и prisma generate)
npm run check:static   # Быстрый тест синтаксиса .ts/.tsx и ссылок
npm run smoke          # HTTP smoke checks; сайт уже должен быть запущен
npm run build          # production build
npm start              # запуск production build
npm run db:studio      # визуальный просмотр таблиц Prisma
npm run db:migrate -- --name next-change  # новая миграция при изменении schema.prisma
```

Для smoke-теста другого адреса укажите `SMOKE_BASE_URL`. Smoke **не создаёт тестовые заказы** и не меняет остатки.

## Как работает оформление заказа

1. Клиент добавляет товар в корзину. Сохраняются `variantId`, размер, цвет и количество.
2. Корзина отправляет `POST /api/cart/quote` — возвращаются актуальные цены/наличие; суммы браузера не считаются доверенными.
3. При отправке заказа сервер повторно валидирует данные и создаёт **транзакцию PostgreSQL** с проверкой остатка (`updateMany`, `stock >= quantity`) и списанием товара. Цены используются только из БД.
4. В транзакции создаётся заказ и снимок позиций. Клиент получает номер формата `NW-YYYYMMDD-XXXXXXXX`.
5. При отмене заказа из админки система пытается восстановить остатки существующих вариантов. Восстановление отменённых заказов автоматически заблокировано.

Это **не платёжная система**, карты и платёжные реквизиты не собираются. После сохранения заказ ожидает ручного подтверждения персоналом.

## Административная панель

- `/admin/login`: вход администратора. Сессия — 7 дней.
- `/admin`: список товаров и операций, статистика, заказы, категории.
- Товар добавляется с названием, латинским `slug`, категорией, описанием, тканью, фотографиями и хотя бы одним вариантом размера/цвета/остатка.
- Фото в local/self-hosted среде кладутся в `public/uploads` и доступны по `/uploads/...`. Ограничение 5 МБ; MIME и сигнатуры JPG/PNG/WEBP проверяются сервером.
- Обновление варианта сохраняет его ID, если размер/цвет остались прежними. При изменении размера/цвета вариант считается новым, старый `variantId` из корзины перестанет быть действителен.
- Удаление категории с товарами запрещено; данные выполненных заказов сохраняют снимок товара даже после удаления товара.

## Основные переменные окружения

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | PostgreSQL connection string. Секрет! |
| `ADMIN_EMAIL` | Email администратора для первого seed. |
| `ADMIN_PASSWORD` | Пароль администратора для seed (16+ символов). Секрет! |
| `NEXT_PUBLIC_SITE_URL` | Публичный URL сайта. |
| `NEXT_PUBLIC_CONTACT_EMAIL` | Контактный адрес для футера (пустое значение скрывает ссылку). |
| `NEXT_PUBLIC_INSTAGRAM_URL` | Полная ссылка на Instagram для футера (пустое значение скрывает ссылку). |

`.env` не включать в git и **не передавать клиенту** переменные без префикса `NEXT_PUBLIC_`.

## Перед реальным запуском бизнеса

Не пропускайте эти действия:

1. **Замените фотографии и контент на достоверные.** Seed-каталог содержит примерные цены, описания, изображения и остатки; не выдавайте их за фактические товары.
2. **Определите доставку, возврат и юридические сведения.** Тариф 300 сом, бесплатная доставка от 5 000 сом — стартовые настройки в `lib/utils.ts`. Укажите реальные условия, контакты продавца, данные компании, юридически выверенную политику конфиденциальности.
3. **Подключите уведомления** по новым заказам (email/SMS/CRM). В текущем проекте заказ записывается в БД и виден в админке, но не рассылается покупателю.
4. **Подключите хранилище фото** (например, S3-совместимое) вместо локального `public/uploads`, если деплоите на serverless/непостоянном файловом хранилище.
5. **Обеспечьте HTTPS, резервные копии, мониторинг и rate limiting** по IP на публичных endpoints, а также защищённый секретами CI/CD, актуальные security updates и аудит зависимостей.
6. **Подключите надёжную оплату** только через официальную интеграцию платёжного провайдера. Настоящие банковские операции в текущем проекте отсутствуют.
7. **Проведите полное браузерное и интеграционное тестирование** на вашем окружении перед публикацией: создание и отмена заказа, конкурирующие покупки, редактор товара, загрузка изображений, адаптивность, скринридер, разные устройства.
8. **Рассмотрите согласие на email-рассылку и механизм отписки.** Сейчас подписка сохраняет email в БД, но рассылка не отправляется и не имеет интерфейса отписки; без этого её нельзя считать готовой массовой маркетинговой системой.

### Безопасность

Админская авторизация проверяется через БД в серверном layout и во всех административных API. Это существенно лучше скрытого интерфейса, но **не заменяет** инфраструктурную защиту: HTTP request limits, мониторинг входов, логирование, WAF при необходимости, безопасный деплой и дополнительные меры по угроз-модели.

## Тестирование проекта в предоставленной среде

Проведена статическая проверка синтаксического дерева TypeScript/TSX и части локальных ссылок. **Полноценный `npm install`, `next build` и браузерный smoke-тест не могли быть выполнены там, где создавался архив**, так как среда не предоставляла доступ к npm registry / запущенному PostgreSQL. Поэтому результат следует считать исходным кодом для запуска и проверки в вашем окружении, а не подтверждённым production-релизом.
